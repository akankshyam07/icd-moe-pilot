Specialty vs. chapter routing for ICD coding: a pilot study

Akankshya MohantyOctober 2026

What I wanted to find out

Our plan is a mixture-of-experts (MoE) model that assigns ICD codes from clinical notes. At our last meeting we discussed splitting the experts by ICD chapter or by medical specialty, using the parent-child structure of the code tree, and stacking specialty and chapter experts so the model gets more specific as the code gets longer.

We can't train on full MIMIC notes yet, so I wanted to answer as much as I could now:

  • Has anyone already compared chapter-based and specialty-based experts for ICD coding?
  • In real MIMIC records, how does a patient's hospital service relate to the ICD chapters they get coded with? How many patients fall under general medicine?
  • On a small open dataset, does routing by specialty or by chapter work better? Does parent-child conditioning help? Does stacking help?

I also wanted a working pipeline, so that when we have the MIMIC notes we can run the same comparison right away.

Key terms

ICD code treeICD-10 codes get more specific as they get longer. A chapter is one of 22 broad groups by body system, a 3-character category is a condition, and the full code adds detail.
Ch. 9 Circulatory (I00–I99)→I21 Acute MI→I21.01 STEMI, left main artery
Mixture of experts (MoE)A model made of several smaller sub-networks ("experts"), each meant to specialize in part of the data, plus a gate that decides how much each expert counts for a given note.
RoutingHow the gate decides. Chapter-routed: one expert per ICD chapter. Specialty-routed: one expert per hospital service. Learned gate: the model makes up its own split.
services tableA MIMIC table that records which hospital service a patient was under during a stay, such as MED (general medicine), CMED (cardiology) or SURG (surgery).
Micro-F1 / macro-F1F1 combines precision (how many predicted codes were right) and recall (how many true codes were found), from 0 to 1. Micro-F1 pools every prediction, so common codes dominate. Macro-F1 averages over codes, so rare codes count equally. "1 point" here means 0.01.
Parent conditioningWhen predicting a full code like I21.01, the model also sees its score for the parent category I21.
FiLMA layer that adjusts the model's internal features using extra information. Here, specialty and chapter adjust the full-code prediction.
Gate entropyHow spread out the gate's choices are, from 0 (each note goes to a single expert) to 1 (spread evenly across all experts).
Seeds and ±Each version was trained 5 times from different random starting points. The ± is the standard deviation: how much results vary between runs. Differences smaller than about twice that aren't reliable.
Bio_ClinicalBERTA language model (BioBERT, further trained on MIMIC-III clinical notes). It turns each note into a list of numbers that the experts then work from. I kept it frozen, so it wasn't trained further.

Summary of results

  • Nonefound

    I couldn't find any paper that compares chapter-routed and specialty-routed experts for ICD coding, or that uses MIMIC's services table to route. Both look like open gaps our project could fill.

  • 40.7%of admissions

    of admissions in the MIMIC-IV Demo start under general medicine (MED). A general-medicine expert would be the biggest one, so whether we keep it as a catch-all or leave those patients out is a real decision.

  • 7.7chapters / stay

    ICD chapters per admission on average. A patient usually has codes from many chapters but only one admitting service.

  • +1.4micro-F1 points

    Routing by specialty did better than routing by chapter at both code levels. No MoE version clearly beat a plain model without experts, though.

  • +1.2micro-F1 points

    Feeding each full code its parent category's score helped. Splitting this into two separate models, one for parent codes and one for full codes, added another 1.2 points, though with twice the parameters. Published hierarchy methods on MIMIC-III report gains of about the same size (+0.9 to +1.2 micro-F1).

What I read

I started by looking for MoE models for ICD coding and for hierarchical (parent-child) coding models evaluated on MIMIC. These are the papers that mattered most for our design:

What I took from the reading:

  • Mixture-of-experts papers in clinical AI split experts by data type (notes, labs, images), not by specialty. Splitting by chapter or specialty hasn't been tested.
  • Hierarchy helps, but by about 1 point, mostly on rare codes. We should expect gains of 1–4 points, not big jumps.
  • HiLAT and HLAN are often called "hierarchical", but they're hierarchical over the document (words, then sentences or chunks), not the code tree. They aren't the right baselines for parent-child coding.
  • The largest combined-model gain I could verify was +1.0 micro-F1 and +4.2 macro-F1 (GPsoap). Bigger numbers I came across were relative improvements, on private data, or from a different task setup.

Data I used and why

Finding the MIMIC-IV Demo

At the meeting I'd brought up MIMIC's services table, which records the hospital service each patient was under (cardiology, neurosurgery and so on), as a possible specialty label. I wanted to see what those rows actually look like and how many patients are general medicine, without waiting for the full database.

PhysioNet publishes the MIMIC-IV Clinical Database Demo: 100 real patients (275 admissions) with the same tables and columns as full MIMIC-IV, and it's open to anyone. It has services and diagnoses_icd, which is exactly what I needed to check the specialty idea. It doesn't include clinical notes.

Notes with ICD codes

To test the coding model itself I needed notes labeled with ICD-10 codes that anyone can download. CodiEsp (CLEF eHealth 2020) has 1,000 Spanish clinical case reports coded in ICD-10, with a machine-translated English version, which is what I used. Its codes use the same tree as MIMIC-IV's ICD-10 codes, so chapters, 3-character categories and full codes all work the same way.

A specialty label for those notes

CodiEsp doesn't say which specialty each case belongs to. MTSamples has about 5,000 transcribed notes labeled by specialty, so I trained a classifier on it and used it to give each CodiEsp note a specialty, standing in for services. I grouped the specialties to match MIMIC's service names.

Specialty classifier · MTSamples

Predicting a specialty for each note

The classifier predicts one of 11 service groups (MED, CMED, SURG, ORTHO, NMED, NSURG, GI, GYN, GU, OMED, PSYCH). It's a TF-IDF and logistic regression model: it scores notes by which words they use and how often, then picks the most likely service. It's simple and fast.

My first version only got 42% accuracy. When I looked into it, MTSamples lists 949 of its 2,094 unique notes under more than one specialty, usually a specific one plus "Surgery". The same note ended up in both training and test with different labels. After keeping one copy of each note and preferring the more specific specialty, accuracy went up to 84% (macro-F1 0.85). Anyone else using MTSamples should watch for this.

What the results say

  • Specialty routing beat chapter routing (0.277 vs. 0.263 on categories, 0.248 vs. 0.234 on full codes), even though the chapter model is twice the size. My explanation: a note covers many chapters, so the chapter gate has to guess them from the text and spreads its weight around, while the specialty is known up front.
  • No MoE version clearly beat the plain model. With 500 training notes, each expert gets very little data. The learned gate put almost everything on 1–2 experts and did worst, which suggests routing should be guided by real labels like chapter or service.
  • Parent conditioning helped full codes (+1.2 micro-F1, +1.4 macro-F1 over the plain model).
  • Two separate models beat one model on full codes (0.266 vs. 0.254 micro-F1), the best full-code score of any version. Two catches: the pair has twice the parameters of the single model, and its macro-F1, which weights rare codes equally, was lower and varied a lot between runs (0.109 ± 0.026). So it may help common codes more than rare ones. Model 1's predictions on its own training notes are also more confident than on new notes, which could matter more on MIMIC.
  • The stacked model had the best category score (0.283), but only by about 1–2 standard deviations. Taking out FiLM, the layer that adjusts the full-code prediction by specialty and chapter, didn't hurt, so that part of the idea needs a different design or more data.
  • Removing the general-medicine expert changed nothing, because only 8% of CodiEsp notes are classified as general medicine. In MIMIC it's 41%, so this test should matter much more there.

Partly. These are the parts I think carry over to MIMIC, and the parts that don't:

So this pilot doesn't settle the chapter-vs-specialty question, but it gives us a tested setup and a first result to check against once we run it on MIMIC notes.

Limitations

  • I kept the encoder frozen and had 500 training notes, so absolute F1 is low (around 0.25). The comparison between versions is the point, not the scores themselves.
  • The error bars only show variation between runs, not how much the 250 test notes affect the result.
  • The specialty classifier is often unsure on CodiEsp (average gate entropy 0.89 out of 1), so the specialty MoE partly acts like an average of experts.

Methods details

Data. MIMIC-IV Demo v2.2: services (first service per admission by transfer time) and diagnoses_icd, with ICD-9 codes mapped to ICD-10 chapters. MTSamples: 4,999 notes reduced to 2,094 after removing duplicates and labels that are note types (Consult, SOAP, Discharge Summary) instead of specialties. CodiEsp English: 500 train / 250 dev / 250 test, keeping codes with at least 3 training occurrences.

Specialty classifier. TF-IDF (1–2-word phrases) with class-balanced logistic regression, 80/20 stratified split.

Coding models. Bio_ClinicalBERT with notes split into 512-token chunks and averaged, encoder frozen. Experts are 128-unit layers. The chapter gate is trained toward each note's chapter distribution; the learned gate has a load-balancing penalty. The two-model version trains a category model first, then a separate full-code model that takes the note plus the first model's category scores. Trained with AdamW and stopped early on the dev set; one decision threshold per code level is tuned on dev. Macro-F1 averages over codes that appear in the test set.

Code. github.com/akankshyam07/icd-moe-pilot: Python scripts for each step plus a Kaggle notebook. Every run uses a fixed seed and reproduces exactly; the full comparison takes around 10 minutes on a laptop.
